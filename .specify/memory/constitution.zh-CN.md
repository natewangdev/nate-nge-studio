# NGE-STUDIO 宪章

本文档约束 **NGE-STUDIO**：一款在 Windows 上运行的桌面应用，用于发现、配置并运行基于
**NGE2** 引擎（`nate-game-engine`）的游戏脚本。功能规格定义*做什么*；本文档定义
*不可协商的怎么做*。

英文权威版（代理执行唯一依据）：[`constitution.md`](./constitution.md)。
执行 Spec Kit 工作流时，代理**必须**仅以英文版为准；本中文版仅供母语为中文的维护者阅读。

## 核心原则

### I. 桌面产品优先

- NGE-STUDIO 是面向终端操作者的**桌面应用**（产品壳），不是可复用库。
- 核心用户价值通过可视化界面交付：脚本目录、启动参数、生命周期控制与实时日志。
- 非 UI 的共享逻辑（目录发现、运行编排、设置持久化）可以放入可 import 模块，但首要交付物
  是可运行的 Windows 应用（含可打包的可执行文件分发）。
- 不得新增仅有组织便利、却无清晰产品或脚本作者契约的模块。

### II. 以 NGE2 为唯一游戏引擎

- Studio 管理的全部游戏脚本**必须**运行在 **NGE2**（`nate-game-engine` 的 `nge2`）之上。
- Studio **必须**将 NGE2 作为 **pip 可安装**依赖（可编辑本地路径和/或已发布分发），不得在本仓
  内嵌引擎分支副本。
- UI 暴露的启动参数**必须**覆盖脚本作者需要的、已文档化的 NGE2 构造参数全集，外加 Studio
  自有控制项（例如运行时长超时）。
- 当 NGE2 公开 API 变更时，Studio **必须**在采用新引擎版本的同一功能变更中更新参数表面与文档。

### III. 打包时脚本目录（不可协商）

- 游戏脚本位于约定目录树下，并在**构建/打包时**发现；不得依赖已交付可执行文件对任意外部目录
  做运行时热扫描来刷新目录。
- 新增游戏文件夹或在游戏下新增脚本后，须**重新构建/打包**，该构建的 UI 才会出现对应目录项。
- 每个脚本目录**必须**包含 **manifest**，描述展示元数据与可选的默认启动参数。文件夹名即为
  稳定的游戏/脚本 ID。
- 脚本**必须**实现 Studio 定义的**统一入口协议**（通过运行上下文协作式暂停/结束）。不符合协议
  的临时入口不在目录支持范围内。

### IV. 协作式生命周期与单实例运行（不可协商）

- 同一时间最多**一个**脚本处于运行中。已有运行时再启动另一个**必须**拒绝，并向用户给出清晰
  原因（HID/设备独占与产品简化）。
- **暂停**为协作式：Studio 发出暂停信号；脚本观察运行上下文并让出。
- **结束**通过运行上下文取消，且在运行结束或中止后 Studio **必须**关闭 NGE2 引擎实例（释放
  设备/后端）。
- 强制杀进程不是主要结束路径。仅在后续功能明确要求时，才可作为超时或不可恢复挂起后的最后手段。

### V. 可观测性与操作者控制

- 脚本运行期间，UI **必须**展示适合操作者阅读的**近实时**日志。
- 启动 / 暂停 / 结束**必须**同时提供界面按钮与**全局快捷键**。
- 快捷键绑定可配置，且**必须**在应用重启后持久化。
- 默认绑定：启动 = F9，暂停 = F10，结束 = F11（各一个绑定）。

### VI. 需求文档双语（不可协商）

- Spec Kit 产出的一切面向需求的 Markdown 产物（包括但不限于功能目录下的 `spec.md`、
  `plan.md`、`tasks.md`、检查清单，以及 clarify/analyze 报告）**必须**同时存在**英文版**与
  **简体中文版**。
- 命名：英文版保留 Spec Kit 规范文件名（如 `spec.md`）；中文版在扩展名前加 `.zh-CN` 后缀
  （如 `spec.zh-CN.md`）。
- 任何创建或更新需求 Markdown 的改动，**必须在同一次变更中**同时更新英文版与中文版。
  禁止只更新一种语言或造成双版漂移。
- 双版内容须信息等价（相同意图、范围、验收标准与约束）。措辞可本地化，事实不得偏离。
- **执行权威**：在规划、实现、分析或收敛时，代理**必须**仅阅读并遵循**英文** Markdown。
  任何中文版（`*.zh-CN.md`）仅供母语为中文的维护者阅读，**无操作效力**，执行 Spec Kit
  决策时**必须忽略**。

### VII. 宪章双语（不可协商）

- 本宪章以双语成对维护：
  - 英文（对代理具有约束力）：`.specify/memory/constitution.md`
  - 简体中文（仅供人阅读）：`.specify/memory/constitution.zh-CN.md`
- 每次修订**必须**在同一次变更中更新**两个**文件，保持信息等价，同步提升 **Version**，
  并设置相同的 **Last Amended**。
- Spec Kit 技能与 implement/converge 流程**必须**仅将英文宪章视为唯一约束来源。
  中文宪章**不得**作为执行输入。

## 平台与产品约束

- **主目标平台**：Windows 桌面。设计、测试与文档以 Windows 为先。
- **UI 技术栈**：Python 桌面 GUI，视觉风格偏现代化与科技感。优先选用 Qt for Python
  （PySide6），除非经正式修订改用其他工具包。
- **分发形态**：将 Windows **可执行文件**（打包应用）作为一等交付物。
- **Python**：以 `>=3.11` 为准，除非同一变更在 `pyproject.toml` 中提高下限。
- **打包事实来源**：`pyproject.toml`（以及文档化的 exe 打包配方）。
- **除非另行规定，否则非目标**：多 OS 对等、多脚本并行运行、云端/多用户账号、第三方脚本市场，
  或替代 NGE2 本身。

## 质量门禁

- 用户可见行为变更：在可行处为编排/目录/设置逻辑提供自动化测试；UI 冒烟路径写入功能计划的
  完成定义。
- 仓库已配置的 lint/format 工具在计划的完成定义中要求时，**必须**通过。
- 非需求迫使的复杂度**必须**拒绝或延后；例外须在计划中说明理由。
- 功能的 Spec Kit 流程：在 plan、tasks、implement/converge 阶段检查宪章合规，而非仅在最后。
- 双语成对：触及需求 Markdown 或宪章的变更，若任一语言版本缺失或过时，则视为未完成。

## 治理

- 本宪章优先于与之冲突的非正式口头约定与临时编码偏好。
- 修订须同时更新 `constitution.md` 与 `constitution.zh-CN.md`，提升宪章 **Version**，并设置
  **Last Amended**。实质性规则变更应在依赖该规则的下一份功能计划中予以说明。
- `/speckit-plan`、`/speckit-tasks`、`/speckit-implement`、`/speckit-converge` **不得**在未经
  明确、书面修订的情况下引入违反本原则的设计。
- 不确定某规则是否适用时，优先更窄的产品表面、单实例运行安全、协作式生命周期，以及更强的
  操作者可见性（日志 + 控制）。
