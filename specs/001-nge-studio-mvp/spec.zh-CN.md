- Q: 脚本运行结束后（空闲），日志面板应清空还是保留该次日志？ → A: 保留上次运行日志，直到下一次启动时清空/替换为新日志流（选项 A）。

- Q: 选择路径后写入绝对还是相对？ → A: 若落在 `resource_dir` 下则写相对路径，否则写绝对路径（选项 B）。
- Q: `resource_dir` 为空或无效时，选择对话框起始目录？ → A: 回退到用户主目录（选项 A）。
- Q: UI 以小时编辑运行时长后，持久化字段是否改名？ → A: 继续存 `run_duration_sec`；UI 按小时编辑，读写换算（小时 × 3600）（选项 A）。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 浏览已打包的游戏与脚本（优先级：P1）

操作者打开 NGE-STUDIO，看到本构建打包时纳入的游戏与脚本。每个脚本展示来自 manifest 的可读元数据。维护者在源码中新增游戏文件夹或脚本文件夹并重新构建后，新构建的 UI 中会出现新项。

**优先级理由**：没有可发现的目录，其余工作室能力没有作用对象。

**独立测试**：用含 sample `game_scripts`（含 manifest）的树进行打包（或与打包相同的目录扫描）；启动应用；核对游戏/脚本与显示名；去掉某脚本后重建；核对有无与打包树一致。

**验收场景**：

1. **给定**某打包构建至少包含一个游戏与一个合法脚本（入口 + manifest），**当**操作者打开目录，**则**游戏与脚本出现，并显示 manifest 显示名（缺失时回退为文件夹 ID）。
2. **给定**某脚本目录缺少必需 manifest 或统一入口，**当**打包/目录校验运行，**则**整次打包/构建失败，并给出能定位到违规路径的清晰错误。
3. **给定**源码中在已有游戏下新增了脚本文件夹，**当**操作者运行该新增之前打好的旧构建，**则**新脚本**不会**出现，直到重新构建/打包纳入它。
4. **给定**多个游戏且各有多个脚本，**当**操作者浏览目录，**则**按游戏分组，且每个脚本可独立选中。

---

### 用户故事 2 - 配置启动参数并点选目标窗口（优先级：P1）

选中脚本后，操作者配置 NGE2 启动参数（构造参数全集）与 Studio 运行时长超时，可选从脚本 manifest 加载默认值。路径类字段支持手输与系统选择对话框。操作者可可视化点选目标窗口，而不必手输句柄；所选句柄写入 hwnd 参数。

**优先级理由**：正确参数与窗口绑定是有效运行的前提。

**独立测试**：选中脚本；编辑各暴露参数；对路径字段使用文件夹/文件选择；对已知窗口使用点选；输入非整数小时超时；确认下次选中该脚本时恢复会话值；清空超时并验证「无 Studio 超时」行为。

**验收场景**：

1. **给定**已选中脚本，**当**操作者查看启动设置，**则** UI 暴露作者所需的、已文档化的 NGE2 构造参数全集（`resource_dir`、`hwnd`、`capture`、`humanize`、`control_mode`、`log_dir`、`yolo_model`、`yolo_names`、`ocr_kwargs`）以及 Studio 自有运行时长超时（以**小时**显示/编辑）。
2. **给定**脚本 manifest 提供默认参数值，**当**操作者首次选中该脚本（或重置为默认），**则**表单填入这些默认值（若存在 `run_duration_sec` 则以小时显示）。
3. **给定**操作者进入窗口点选模式，**当**其选中一个非 Studio 自身的可见顶层窗口，**则**对应窗口句柄写入 hwnd 字段，并显示可识别的窗口标题/标签。
4. **给定**操作者进入窗口点选模式，**当**其试图选中 NGE-STUDIO 自身窗口，**则**拒绝该选择，hwnd 不改为 Studio 句柄，并提示操作者改选其他窗口。
5. **给定**操作者以小时设置了正数运行时长超时（含非整数如 `0.5`），**当**运行超过该时长，**则** Studio 使用与手动结束相同的路径停止运行（取消 + 关闭引擎）。
6. **给定**操作者将运行时长留空/禁用，**当**脚本运行，**则** Studio 不会仅因时间流逝而停止它。
7. **给定**操作者编辑过某脚本参数，**当**其离开并在同一用户配置/本机设置存储中再次选中该脚本，**则**恢复上次使用的参数值。
8. **给定**有效的 `resource_dir`，**当**操作者对 `resource_dir` 或 `log_dir` 使用「选择」，**则**打开文件夹对话框（在应起始于资源目录时从该目录打开），并将所选文件夹写入字段；也可手输路径。
9. **给定**有效的 `resource_dir`，**当**操作者对 `yolo_model` 或 `yolo_names` 使用「选择」，**则**打开文件对话框并以 `resource_dir` 为起始目录（建议过滤 `*.onnx` / `*.names`+`*.txt`，另有所有文件）；所选路径若在 `resource_dir` 下则写相对路径，否则写绝对路径；`ocr_kwargs` 仍为 JSON 文本，**不提供**文件选择。
10. **给定** `resource_dir` 为空或不是已存在目录，**当**操作者打开本应以 `resource_dir` 为起始的路径选择对话框，**则**改为从用户主目录起始。
11. **给定**启动参数表单可见，**当**操作者比较「点选窗口」按钮与路径「选择」按钮相对同行输入框，**则**这些按钮与相邻输入框高度一致。

### 用户故事 3 - 启动、暂停与结束脚本（优先级：P1）

操作者用当前参数启动所选脚本。同一时间只能有一个运行。可协作式暂停与恢复（暂停时启动/F9 充当恢复），以及结束以取消并释放引擎。相同动作可通过界面按钮与全局快捷键（默认 F9/F10/F11）触发；快捷键可修改并持久化。

**优先级理由**：生命周期控制是工作室的核心操作闭环。

**独立测试**：运行遵守暂停/结束的样例脚本；分别用 UI 按钮与快捷键；运行中尝试第二次启动；验证结束后引擎资源释放；修改快捷键后重启应用再验证绑定。

**验收场景**：

1. **给定**已选中脚本、参数合法且无活动运行，**当**操作者按下启动（UI 或快捷键），**则** Studio 用这些参数构造 NGE2，以统一入口与运行上下文调用脚本，并显示运行中状态。
2. **给定**已选中脚本、hwnd 留空且其余参数合法，**当**操作者按下启动，**则** Studio 启动成功，且 NGE2 将坐标视为屏幕绝对物理像素（无窗口绑定）。
3. **给定**脚本正在运行，**当**操作者按下暂停，**则**运行上下文报告已暂停，合规脚本在恢复前停止推进工作（协作式）。
4. **给定**处于暂停的运行，**当**操作者按下启动/恢复（暂停期间「启动」控件与 F9 快捷键充当恢复），**则**运行上下文清除暂停，脚本可继续。
5. **给定**运行中或已暂停的脚本，**当**操作者按下结束，**则**运行上下文发出取消信号，脚本入口协作式返回/中止，且 Studio 关闭 NGE2 引擎实例。
6. **给定**已有活动运行，**当**操作者尝试启动另一脚本（或再次启动同一脚本），**则** Studio 拒绝并说明仅允许一个运行。
7. **给定**默认快捷键，**当**应用运行且快捷键启用时操作者按下 F9 / F10 / F11，**则**即使其他窗口处于前台，也分别触发启动 / 暂停 / 结束（全局）。
8. **给定**操作者在设置中更改了快捷键绑定，**当**其重启应用，**则**新绑定仍然生效。

### 用户故事 4 - 运行中查看实时日志（优先级：P2）

脚本运行（或暂停）期间，操作者在滚动的实时日志面板中查看引擎/脚本日志输出，延迟低到足以用于监控。结束后这些行仍保留，直到下一次启动。

**优先级理由**：操作者需要可见性以诊断卡住或配置错误的运行，而无需外挂调试器。

**独立测试**：运行周期性打日志的样例脚本；验证行按序出现在 UI；结束后确认面板保留该次运行的行，直到下一次启动。

**验收场景**：

1. **给定**正在运行的脚本会发出日志行，**当**操作者查看日志面板，**则**新行无需手动刷新即出现，且按时间顺序。
2. **给定**日志量很大，**当**面板更新，**则** UI 仍可用（操作者仍可按结束）；超过文档化上限后可丢弃最旧行。
3. **给定**一次完成或结束后无活动运行，**当**操作者查看日志面板，**则**仍能看到该上次运行保留的行（不是另一脚本的实时流）。
4. **给定**已保留上次运行的行，**当**操作者启动新一次运行，**则**日志面板清空（或替换）这些行，并开始显示新运行的日志流。

---

### 用户故事 5 - 打成并启动 Windows 可执行文件（优先级：P2）

维护者产出包含已打包脚本目录的 NGE-STUDIO Windows 可执行文件构建。操作者在受支持的 Windows 机器上启动该 exe，无需作为用户步骤单独安装 Python 工具链即可使用目录/运行流程。

**优先级理由**：以 exe 分发是明确的产品要求。

**独立测试**：用至少一个样例脚本构建打包 exe；在较干净的 Windows 环境运行；按计划完成定义验证目录与干跑/mock 运行路径。

**验收场景**：

1. **给定**打包流水线成功，**当**维护者完成发布构建，**则**产出 Windows 可执行文件产物，并嵌入/捆绑该构建的脚本目录。
2. **给定**受支持 Windows 系统上的打包 exe，**当**操作者双击/启动它，**则**主 UI 打开且目录与打包内容一致。

### 边界情况

- 无效 hwnd（点选后窗口已关闭）：在引擎构造前或构造时启动失败并给出清晰错误；不留下僵尸运行状态。
- 缺失 `resource_dir` 或 YOLO 模型路径：启动失败，Studio 和/或 NGE2 给出可操作错误；UI 展示消息。
- 脚本忽略协作式暂停/结束：结束仍尝试取消 + 关闭引擎；若入口在文档化宽限期内未返回，Studio 展示脚本挂起警告（强制杀死可选，MVP 除非计划采纳否则不要求）。
- 快捷键与其他全局钩子冲突：Studio 报告注册失败，并清晰保持上一绑定或未绑定状态。
- 有 manifest 但 JSON/字段损坏：整次打包/构建失败，并给出能定位到违规路径的清晰错误。
- 操作者点选到 Studio 自身窗口：拒绝该选择；hwnd 不变；提示操作者改选其他窗口。
- 设置了 `window_title` 且无匹配的可见顶层窗口：启动失败并给出清晰错误；不开始运行会话。
- 同时设置 `hwnd` 与 `window_title`：用 hwnd 构造 NGE2；标题不用于解析。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统**必须**在 Windows 上提供现代化、偏科技感的可视化桌面 UI，用于管理 NGE2 游戏脚本。
- **FR-002**：系统**必须**在构建/打包时从约定源码树 `game_scripts/<game_id>/<script_id>/` 发现游戏/脚本（开发态使用与打包相同的目录规则）。
- **FR-003**：每个脚本目录**必须**包含 `manifest` 文件与统一入口模块；若任一被发现的脚本目录违反已文档化协议或 manifest 规则，打包/目录校验**必须**使整次构建失败（清晰错误须指明路径）。
- **FR-004**：Manifest **必须**至少支持：显示名、可选描述、可选默认启动参数。游戏 ID 与脚本 ID **必须**为文件夹名。
- **FR-005**：选中脚本后**必须**可配置完整 NGE2 构造参数表面：`resource_dir`、`hwnd`、`window_title`、`capture`、`humanize`、`control_mode`、`log_dir`、`yolo_model`、`yolo_names`、`ocr_kwargs`，以及 Studio 运行时长超时。`hwnd` 与 `window_title` 均**必须**可选。二者皆空时仍**必须**允许启动，并采用 NGE2 屏幕绝对坐标语义。
- **FR-005a**：`resource_dir` 与 `log_dir` **必须**各提供文本输入与「选择」控件，打开**文件夹**对话框；也允许手输路径。
- **FR-005b**：`yolo_model` 与 `yolo_names` **必须**各提供文本输入与「选择」控件，打开**文件**对话框（建议过滤：模型 `*.onnx`；names `*.names` 与 `*.txt`；另有所有文件）。`ocr_kwargs` **必须**保持可编辑 JSON 文本，且**不得**提供文件「选择」。
- **FR-005c**：路径/文件选择对话框在当前 `resource_dir` 为非空且已存在的目录时**必须**以该目录为起始；否则**必须**以用户主目录为起始。成功选择后，若路径位于 `resource_dir` 下，字段**必须**存相对路径；否则**必须**存绝对路径。
- **FR-005d**：Studio 运行时长在 UI 中**必须**以**小时**编辑（允许非整数，如 `0.5`）。持久化与 runner **必须**继续使用 `run_duration_sec`（秒 = 小时 × 3600）。空/省略/≤0 表示无 Studio 超时。
- **FR-005e**：「点选窗口」按钮与路径「选择」按钮**必须**与同行相邻输入框视觉高度一致。
- **FR-005f**：启动参数**必须**包含可选 `window_title`（字符串）。构造 NGE2 前解析：(1) 若已设 `hwnd` 则用之；(2) 否则若 `window_title` 非空，则查找标题**包含**该查询（大小写不敏感，与 NGE2 `find_by_title` 一致）的可见顶层窗口，并绑定**第一个**匹配的 hwnd；(3) 否则未绑定。若 (2) 无匹配，启动**必须**失败并给出清晰 UI 错误。
- **FR-005g**：当 NGE2 以绑定 hwnd 构造完成（来自 hwnd 字段或标题解析）后，Studio 在调用脚本 `run` 之前**必须**成功调用 `engine.window.activate()`。若激活失败，启动**必须**失败、给出清晰错误并关闭引擎。
- **FR-006**：系统**必须**提供可视化窗口点选，以将用户所选顶层窗口填入 `hwnd`。选中 NGE-STUDIO 自身窗口**必须**被拒绝并给出清晰提示；hwnd **不得**设为 Studio 自身句柄。点选**可以**同时将窗口标题填入 `window_title` 以便操作者对照。
- **FR-007**：系统**必须**在同一机器/用户配置下，跨应用重启持久化每脚本上次启动参数与全局快捷键绑定。
- **FR-008**：系统**必须**通过 UI 控件以及三个可配置全局快捷键（默认 F9 / F10 / F11）支持活动运行的启动、协作式暂停与结束。暂停期间，「启动」控件及其快捷键**必须**充当恢复（不要求单独的恢复控件）。
- **FR-009**：系统**必须**同一时间最多允许一个活动脚本运行，并以清晰消息拒绝额外启动。
- **FR-010**：脚本**必须**通过统一入口协议调用，该协议接收 NGE2 引擎实例与暴露暂停及取消/结束信号的运行上下文。
- **FR-011**：在结束（或 Studio 超时）时，系统**必须**通过运行上下文发出取消信号，并在运行结束时关闭 NGE2 引擎实例。
- **FR-012**：当设置了 Studio 运行时长超时且到期时，系统**必须**使用与手动结束相同的取消 + 关闭引擎路径停止运行。
- **FR-013**：系统**必须**在 UI 中展示活动运行的近实时日志输出。运行结束后，面板**必须**保留该次运行的行，直到下一次启动清空或替换为新运行的日志流。
- **FR-014**：系统**必须**通过 pip 依赖 `nate-game-engine` / `nge2`（可编辑本地路径和/或已发布包），而非内嵌引擎副本。
- **FR-015**：系统**必须**可打成包含该构建脚本目录的 Windows 可执行文件。
- **FR-016**：在源码中新增游戏/脚本后，**必须**重新构建/打包，才会出现在该构建的 UI 目录中。
- **FR-017**：在 `game_scripts/<game_id>/` 下**必须**支持可选的 `common.py`（共享方法）与 `rules.py`（共享规则）供该游戏脚本使用。目录发现**不得**将其视为脚本。Studio **必须**保证脚本可导入它们（例如加载 `main` 时将游戏目录加入 `sys.path`）。`demo` **必须**包含使用示例。

### 关键实体

- **游戏（Game）**：`game_scripts` 下由 `game_id` 标识的文件夹；归组相关脚本。
- **脚本（Script）**：某游戏下由 `script_id` 标识的文件夹；含 manifest、统一入口，以及参数可能引用的资源。
- **Manifest**：脚本的元数据与可选默认启动参数。
- **启动配置（Launch Configuration）**：面向操作者的参数集（NGE2 构造字段 + Studio 超时），含上次使用值。
- **运行上下文（Run Context）**：向运行中的脚本入口传递协作式暂停与取消/结束信号。
- **运行会话（Run Session）**：唯一活动执行（脚本身份、状态：空闲/运行/暂停/结束中、关联日志）。
- **快捷键绑定（Hotkey Binding）**：启动/暂停/结束动作到全局组合键的映射，持久化于设置。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：操作者可在 3 分钟内打开应用、选中已打包样例脚本、设置参数（含窗口点选）并启动运行，无需阅读应用内标签以外的外部文档。
- **SC-002**：某一构建 UI 目录中出现的脚本，100% 存在于该构建打包的 `game_scripts` 树中；仅在打包后才加入源码的脚本绝不会出现在旧构建中。
- **SC-003**：对合规样例脚本，暂停信号发出后 2 秒内可观察进展停止；正常情况下结束使 UI 在 5 秒内回到空闲且引擎资源已释放。
- **SC-004**：样例脚本至少每秒打一条日志时，在典型开发机上 UI 日志面板感知延迟低于 1 秒。
- **SC-005**：更改快捷键并重启应用后，新绑定无需再次配置即可首次生效。
- **SC-006**：维护者可通过文档化打包路径产出 Windows 可执行文件产物，操作者无需手动安装 Python 即可启动该产物并看到已打包目录。

## 假设

- 目标操作者为控制本机的本地 Windows 用户；MVP 不含多用户账号或远程编排。
- 验收测试所需的样例/演示游戏脚本将放入仓库 `game_scripts/`。
- NGE2 仍为唯一支持引擎；脚本不嵌入其他自动化栈。
- 「完整 NGE2 构造参数」指面向作者的、已文档化的公开构造字段；内部工厂钩子（`capture_factory`、`transport_factory`、`ocr_factory`、`yolo_factory`）为高级/测试开关，**不在 MVP UI**，除非后续澄清纳入。
- 启动时 `hwnd` 与/或 `window_title` 可留空；皆空时行为与 NGE2 未绑定窗口（屏幕绝对坐标）语义一致。仅标题时由 Studio 解析 hwnd；已设 hwnd 时以 hwnd 为准。
- 游戏级 `common.py` / `rules.py` 为同一游戏文件夹内共享代码的作者约定，不是目录条目。
- MVP 中 `ocr_kwargs` 以高级结构化字段（JSON 文本）暴露，而非大型专用表单或文件选择器。
- 路径浏览 UX（`resource_dir`/`log_dir` 选文件夹，YOLO 字段选文件，落在 `resource_dir` 下则相对路径，否则绝对路径，无效时回退主目录）仅作用于启动参数表单，不改变 NGE2 构造语义。
- 运行时长**显示单位为小时**；manifest 与 settings 中规范存储字段仍为 `run_duration_sec`，以保持兼容。
- 全局快捷键需要相应 OS 权限；失败模式在应用内报告。
- 视觉设计方向（现代 + 科技）在实现计划/UI 指南中细化，不阻塞本规格。
- 打包工具选择（如 PyInstaller 或其他）属计划决策；产品要求仅到「Windows exe」。
