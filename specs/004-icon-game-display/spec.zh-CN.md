# 功能规格：应用图标与游戏显示名

**功能分支**：`004-icon-game-display`

**创建日期**：2026-09-30

**状态**：草稿

**输入**：用户描述：「为工具添加符合“脚本”主题的应用图标；为游戏目录增加 `display_name`（对齐现有脚本 manifest 模式）。」

**权威说明**：英文版 [`spec.md`](./spec.md) 为 Spec Kit 执行权威。本文件为中文对照。产品基线见 [`../001-nge-studio-mvp/spec.md`](../001-nge-studio-mvp/spec.md)。

## 澄清记录

### Session 2026-09-30

- Q: 应用图标须出现在哪些位置？ → A: 主窗口、任务栏，以及打包后的 Windows 可执行文件（同一套「脚本」主题图标）。
- Q: 游戏级显示名存放何处？ → A: 可选的 `game_scripts/<game_id>/manifest.json`（仅游戏元数据；与 `<script_id>/` 下的脚本 manifest 区分）。
- Q: 游戏 `display_name` 是否必需？ → A: 与脚本一致——元数据文件可选；`display_name` 可选；缺失/空时 UI 回退为 `game_id`。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 通过脚本主题图标识别 Studio（优先级：P1）

操作者启动 NGE-STUDIO（开发入口或打包 Windows 可执行文件）后，能通过一致的、符合「脚本 / 自动化」主题的应用图标立刻识别本产品。同一套品牌出现在主窗口、任务栏与打包 exe 上。

**优先级理由**：没有产品图标时，多窗口场景下难辨认，且交付物显得未完成。

**独立测试**：启动应用与打包构建；确认窗口装饰、任务栏按钮与 `.exe`（或其快捷方式）使用同一图标。

**验收场景**：

1. **给定** NGE-STUDIO 正在运行，**当**操作者查看主窗口与任务栏按钮，**则**两者均显示产品的脚本主题图标（而非系统默认通用应用图标）。
2. **给定**已打包的 Windows 构建，**当**操作者在资源管理器中查看可执行文件（或启动它），**则**该 exe 使用同一套脚本主题图标。
3. **给定**操作者同时打开多个应用，**当**其扫视任务栏，**则**无需先读窗口标题即可凭脚本主题图标区分 NGE-STUDIO。

---

### 用户故事 2 - 按可读显示名浏览游戏（优先级：P1）

操作者打开目录后，若维护者提供了游戏显示名，则按游戏分组时看到可读名称。脚本行仍使用脚本 `manifest.display_name`。维护者可在游戏文件夹下添加可选的游戏级 `manifest.json`；缺失时仍显示文件夹 `game_id`。

**优先级理由**：游戏文件夹 ID（如 `demo`、`diablo4`）对操作者不够友好；与脚本显示名对齐可提升可读性且不改动稳定 ID。

**独立测试**：准备 (a) 有合法游戏 `manifest.json` + `display_name` 的游戏、(b) 无游戏 manifest 的游戏、(c) 有文件但 `display_name` 为空/缺失的游戏；核对 UI 标签，并确认 (b)/(c) 目录校验仍通过。

**验收场景**：

1. **给定**存在含非空 `display_name` 的 `game_scripts/<game_id>/manifest.json`，**当**操作者打开目录，**则**该游戏分组标签显示 `display_name`（而非仅原始 `game_id`）。
2. **给定**某游戏文件夹没有 `manifest.json`，**当**操作者打开目录，**则**分组标签为 `game_id`，且目录校验**不会**仅因缺少游戏 manifest 而失败。
3. **给定**游戏 `manifest.json` 存在但 `display_name` 缺失或为空/空白，**当**操作者打开目录，**则**分组标签回退为 `game_id`。
4. **给定**游戏 `manifest.json` 存在但不是合法 JSON 或违反已文档化的游戏 manifest 字段规则，**当**打包/目录校验运行，**则**整次构建/校验失败，并给出能定位到违规游戏路径的清晰错误。
5. **给定**同时存在游戏级与脚本级 `manifest.json`，**当**发现运行，**则**游戏元数据仅来自游戏文件夹的 `manifest.json`，脚本元数据仍仅来自各脚本文件夹的 `manifest.json`；目录发现**不得**把游戏级文件当成脚本条目。

---

### 边界情况

- 游戏 `manifest.json` 含未知顶层键：目录校验失败（严格），并给出路径 + 原因（与脚本 manifest 严格性一致）。
- 游戏 `manifest.json` 为空对象 `{}`：合法；UI 使用 `game_id`。
- 游戏文件夹仅有 `manifest.json`、无脚本：沿用 MVP 空游戏行为；若有显示名仍可展示。
- 声称交付品牌图标的构建缺失图标资源：打包或启动须让维护者在交付前可察觉（实现本功能后，发布路径不得静默退回系统默认图标）。
- 某游戏无游戏 manifest 时，不得改变其下脚本发现或脚本显示名。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统**必须**为 NGE-STUDIO 提供一套「脚本 / 自动化」主题的产品图标。
- **FR-002**：应用运行时，主窗口及其任务栏呈现**必须**使用该产品图标。
- **FR-003**：打包后的 Windows 可执行文件**必须**嵌入/使用同一产品图标，使资源管理器与启动界面显示该图标。
- **FR-004**：图标主题**必须**传达「脚本」/ 脚本化自动化含义（而非空白通用标记）。具体画稿由实现/资产决定，只要在窗口、任务栏与 exe 上可辨认即可。
- **FR-005**：目录发现**必须**支持可选的游戏级元数据文件 `game_scripts/<game_id>/manifest.json`。
- **FR-006**：游戏级 `manifest.json` 若存在，**必须**允许可选字符串 `display_name`。空或缺失时 UI **必须**显示 `game_id`。本功能契约可另列可选字段（至少 `display_name`；可选 `description` 可与脚本对齐，但非 UI 验收必需）。
- **FR-007**：缺少游戏级 `manifest.json` **不得**单独导致目录校验失败；UI **必须**对该游戏显示 `game_id`。
- **FR-008**：若游戏级 `manifest.json` 存在但损坏或违反已文档化规则，打包/目录校验**必须**使整次构建失败，并清晰指明路径（与 001 脚本 manifest 失败策略一致）。
- **FR-009**：目录 UI **必须**用解析后的游戏显示名（`display_name` 或回退 `game_id`）展示游戏分组。脚本行标签仍由脚本 manifest 驱动（同 001）。
- **FR-010**：稳定标识仍为文件夹名：`game_id` / `script_id` **不得**被显示名替换用于设置键、运行器身份或持久化。
- **FR-011**：目录发现**不得**将游戏级 `manifest.json`、`common.py`、`rules.py` 视为脚本目录（扩展 001 FR-017）。

### 关键实体

- **游戏（Game）**：`game_scripts` 下由 `game_id` 标识的文件夹；可选游戏级 `manifest.json`；分组脚本；向 UI 暴露解析后的 `display_name`。
- **游戏 Manifest**：可选的游戏元数据（`display_name`，若文档化则可含 `description`）；不含启动 `defaults`（仍仅属脚本）。
- **脚本 Manifest**：不变——位于 `game_scripts/<game_id>/<script_id>/manifest.json`。
- **产品图标**：NGE-STUDIO 的脚本主题视觉标识，用于窗口、任务栏与打包 exe。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：在典型操作者机器上，观察者可在 3 秒内仅凭任务栏图标识别正在运行的 NGE-STUDIO，无需先读标题。
- **SC-002**：打包 Windows 构建的可执行文件在启动前于资源管理器中显示产品图标（目视：非通用应用字形）。
- **SC-003**：目录中至少包含一个有 `display_name` 的游戏与一个无游戏 manifest 的游戏时，操作者首次打开即可看到两处预期分组标签，无需额外配置。
- **SC-004**：目录校验对 100% 的非法游戏 `manifest.json`（坏 JSON / 非法字段）以构建失败上报，且路径指向违规游戏文件夹。
- **SC-005**：引入游戏显示名后，既有按 `game_id/script_id` 键控的脚本选择、启动与设置继续可用（无需为旧设置重新配置）。

## 假设

- 图标画稿在实现本功能时提供/制作并纳入仓库；操作者不上传自定义图标。
- 「脚本主题」指清晰传达脚本/自动化的桌面工具视觉线索；细则留给实现，只要满足 FR-001–FR-004。
- 游戏 `manifest.json` 不携带启动默认值；默认值仍只在脚本 manifest 中。
- 仓库样例游戏可补充中英文 `display_name` 以提升可读性；这是内容，不是新的本地化系统。
- 目录树内的每游戏/每脚本图标不在范围内。
- 托盘图标、安装器品牌与网站 favicon 不在范围内（除非已由上述窗口/任务栏/exe 表面覆盖）。
- 本功能不改变 NGE2 引擎 API 或脚本 `run` 协议。
