# 功能规格：脚本自停、脚本参数、时长到期动作

**功能分支**：`006-script-control-params`

**创建日期**：2026-10-02

**状态**：草稿

**输入**：用户描述：「(1) 脚本运行中可主动结束；(2) 每脚本可设不同于 NGE2 的启动参数；(3) 设置了运行时长时可选手动到期动作：无 | 关机（默认无）；关机则强制关机。」

**权威说明**：英文版 [`spec.md`](./spec.md) 为 Spec Kit 执行权威。扩展 001 的 RunContext / 启动表单 / manifest。

## 澄清记录

### Session 2026-10-02

- Q: 脚本如何主动结束？ → A: `ctx.request_stop()`；应尽快返回；与 UI 结束同一生命周期（选项 A）。
- Q: 脚本参数如何声明与注入？ → A: manifest `script_params`；UI 动态字段；经 **`ctx.script_params`** 读取；`run(engine, ctx)` 签名不变（选项 A）。
- Q: 「关机」何时执行？ → A: **仅** Studio 运行时长到期且动作为关机：先停脚本并关引擎，再强制关机。手动结束与脚本 `request_stop` **不**关机（选项 A）。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 脚本请求自行结束（优先级：P1）

作者在逻辑完成时调用 `ctx.request_stop()`。Studio 按操作者结束处理：协作取消已置位，`run` 返回，关引擎，UI 回空闲。

**验收要点**：`request_stop` 后 `should_stop` 为真；正常返回则空闲且引擎关闭；不因此触发关机；挂起宽限同 001。

---

### 用户故事 2 - 每脚本自有参数（非 NGE2）（优先级：P1）

manifest 声明 `script_params`；UI 单独展示；启动时 `ctx.script_params` 可读；按脚本持久化上次值。无声明则空映射。非法 schema 目录校验失败。

---

### 用户故事 3 - 时长到期动作：无 / 关机（优先级：P1）

有正数运行时长时可选 **无**（默认）或 **关机**。无为现 FR-012。关机仅在超时停跑完成后再强制关机。手动结束 / `request_stop` 不关机。

---

### 边界情况

- 暂停中 `request_stop`：结束优先（与 UI 结束一致）。
- 参数类型不符：启动拒绝并提示。
- 关机命令失败：已停脚本；UI/日志报错；机器可能仍开机。
- 清空时长后：到期关机不生效（等同无）。

## 需求 *(必填)*

- **FR-001**：`RunContext` **必须**提供脚本可调用的 `request_stop()`。
- **FR-002**：脚本自停 **必须**走与手动结束相同的拆卸；**不得**单独触发关机。
- **FR-003–FR-008**：可选 `script_params` schema；UI 分栏；`ctx.script_params`；持久化；校验硬失败；类型至少 `string`/`int`/`number`/`bool`/`choice`。
- **FR-009–FR-013**：时长到期动作 无|关机；关机仅超时后；可注入关机执行器供测试。

## 成功标准 *(必填)*

- **SC-001**：样例脚本 Start 后 2s 内 `request_stop`，正常情况下 5s 内回空闲并释放引擎。
- **SC-002**：至少两个 script_params 值可在首次启动时被脚本原样读到。
- **SC-003**：动作为无时超时不调用关机执行器。
- **SC-004**：动作为关机时超时后关机执行器恰好调用一次，且在停止信令之后。
- **SC-005**：非法 `script_params` 夹具 100% 校验失败并带路径。

## 假设

- Windows 强制关机等价于带 force、短/零延时的 shutdown；具体命令行藏在可替换执行器后。
- 超时时不再弹确认（操作者已选关机）；关机前打日志。
- `script_params` 的 id 为稳定标识符；NGE2 defaults / 运行时长 / 到期动作不放进 `script_params`。
