# 研究：008 目录排序

**日期**：2026-10-04

> 英文权威版：[research.md](./research.md)。执行 Spec Kit 时忽略本中文版。

## R1 — 在何处排序

- **决策**：在 `discover_catalog` 中，构建每个游戏的脚本列表之后、收集完全部游戏之后排序。`catalog_panel` 仍按列表顺序插入（不加 UI 排序）。
- **理由**：UI、CLI、测试同一真相源。
- **备选**：仅在树控件排序 — 否决（CLI/测试会分叉）。

## R2 — 排序键

- **决策**：有显式整数时用 `(0, sort_order, folder_id)`；缺失时用 `(1, 0, folder_id)`。
- **理由**：符合 FR-005，且不与作者写的数字哨兵冲突。
- **备选**：缺失当作 `0` — 否决（澄清选项 A）。

## R3 — 整数类型

- **决策**：仅接受 JSON 整数：`isinstance(value, int) and not isinstance(value, bool)`。拒绝浮点、字符串、作为“已出现”的 null、布尔。
- **理由**：FR-009；Python 中 `bool` 是 `int` 子类。
- **备选**：把 `1.0` 强制成 `1` — 否决（严格目录）。

## R4 — 样例内容

- **决策**：仓库 `game_scripts` **可以**写 `sort_order` 作演示；字段可选，不强制改现有树。
- **理由**：内容，不是新系统。

## R5 — 空游戏

- **决策**：不改变现有发现：无脚本目录的游戏不进入返回列表。规格中空游戏条款仅在其被展示时适用。
- **备选**：仅为排序而开始列出空游戏 — 否决。
